# skill 管理器桌面版设计文档

**日期：** 2026-05-16  
**目标：** 将现有的 `skill 管理器` 本地网页应用包装成 Windows 桌面软件，提供独立窗口、托盘功能、免安装版和安装版，并支持可选开机自启动。

## 一、范围

本次桌面化包含以下能力：

- 保留现有 skill 管理器的全部核心功能
- 提供原生桌面窗口承载管理界面
- 提供系统托盘菜单
- 支持关闭窗口后最小化到托盘
- 提供“开机自启动”开关
- 输出两种交付形式：
  - 免安装版 `.exe`
  - 安装版安装程序

本次不包含：

- macOS 或 Linux 打包
- 云端同步
- 多用户配置隔离
- 在线更新机制

## 二、方案选择

采用 `Tauri` 作为桌面壳方案。

原因：

- 现有项目已经具备稳定的前端页面和本地服务逻辑
- Tauri 更适合把网页界面包装成资源占用较低的桌面程序
- Windows 下窗口、托盘、自启动和打包能力都具备
- 相比 Electron，最终体积更小

## 三、总体架构

桌面版分为三层：

### 1. 桌面壳

由 Tauri 负责：

- 创建主窗口
- 注册系统托盘
- 处理窗口显示/隐藏
- 处理最小化到托盘
- 管理开机自启动
- 产出安装版与免安装版

### 2. 本地服务层

继续复用现有 Node.js 服务逻辑，负责：

- 扫描用户、系统、插件 skill
- 实时监听新增、删除、修改
- 生成自动简介
- 保存手动覆盖说明
- 保存活动记录与本地状态

### 3. 前端界面层

继续使用现有 HTML/CSS/JavaScript 界面，负责：

- 分组展示 skill
- 搜索与筛选
- 查看详情
- 编辑手动说明
- 查看活动记录
- 展示桌面设置项

## 四、运行模型

桌面软件启动时执行以下流程：

1. 启动本地服务层
2. 打开主窗口
3. 主窗口加载本地服务提供的管理页面
4. 注册托盘菜单
5. 根据用户配置决定是否启用开机自启动

运行期间：

- skill 目录发生变化时，后台服务自动更新数据
- 前端页面通过现有事件流自动刷新
- 用户关闭窗口时，不直接退出程序，而是隐藏到托盘
- 用户可从托盘恢复窗口或退出程序

## 五、桌面交互设计

### 主窗口

主窗口仍显示当前 skill 管理器页面，保留：

- 顶部总览
- 左侧分组
- 中间 skill 列表
- 右侧详情
- 活动记录

### 关闭行为

- 点击窗口关闭按钮：隐藏到托盘
- 托盘菜单点击“退出软件”：彻底退出

### 托盘菜单

至少提供以下菜单项：

- 显示窗口
- 隐藏窗口
- 开机自启动：开 / 关
- 退出软件

### 设置区

在现有页面中增加一个桌面设置区，展示：

- 开机自启动状态
- 后台监测状态
- 本地数据保存路径
- 当前监测范围

## 六、数据与兼容性

桌面版继续沿用现有本地数据文件：

- `data/skill-state.json`
- `data/overrides.json`

这样网页版已有数据可以被桌面版继续读取，避免迁移成本。

若桌面壳启动目录变化，则需要将数据目录改为稳定的应用数据目录，但对外展示逻辑不变。

## 七、打包输出

计划输出：

- 免安装版：单独可运行的 `.exe`
- 安装版：Windows 安装程序

启动后用户无需手动打开浏览器，只需双击软件即可进入管理界面。

## 八、验证标准

满足以下条件即可视为桌面化完成：

- 双击桌面程序可以打开主窗口
- 主窗口能正常展示当前 skill 数据
- 托盘菜单可用
- 关闭窗口后程序仍在托盘中运行
- 手动从托盘恢复窗口成功
- 可切换开机自启动开关
- 打包产物包含免安装版和安装版
- 现有 skill 自动简介、手动覆盖、活动记录功能保持可用

## 九、实施边界

为了降低风险，桌面化阶段不重写业务逻辑：

- 不重构 skill 扫描器
- 不重写前端页面
- 仅新增桌面壳、桌面设置桥接和打包配置

这样可以保证：

- 复用现有验证通过的逻辑
- 缩短桌面化时间
- 降低引入新 bug 的概率

## 十、规格自检

- 范围清晰，只做 Windows 桌面化
- 方案、窗口行为、托盘行为、自启动方式都已明确
- 没有待定项和占位符
- 架构上保持对现有网页版最小侵入
